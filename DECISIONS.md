| 2026-11-14 | SelfGraph not on the answer path | Stores all relations as one RELATES edge type with etype property; old revisions remain as edges | SELFGRAPH.md S-SG1 |
| 2026-11-14 | Scoring is exact-match on gold entity ids; no LLM judge | Deterministic, cheap, many seeds; removes "model graded itself" attack | PRD §3 |
| 2026-11-14 | Local dev S3 is `moto_server` on the host, not MinIO in compose; the local hydradb service runs with `network_mode: host` | `minio/minio:latest` no longer exists on Docker Hub (S16), and `ufw` on the build host drops docker-bridge traffic to a host-side endpoint (S18). moto needs no image pull and is confirmed to carry HydraDB's conditional writes across a restart (S17). | REALITY_SPIKES S16, S17, S18 |
| 2026-11-14 | Relation types are named and directed so every question path is traversable outgoing-only: `OWNS` → `OWNED_BY` (Service→Team), `ON_CALL_FOR` → `ON_CALL` (Team→Person), `CUSTOMER_OF` → `SERVES` (Service→Customer); `DOCUMENTED_BY` added for Runbook | HydraDB path search is directed and takes one relationship type per MATCH pattern, and our searches run `relDirection: 'outgoing'` from the question's seed entity, so an edge pointing the other way is unreachable. `ON_CALL` is single-valued per team so `page_owner` has one gold answer instead of a refused tie. | PRD §4, §6, REALITY_SPIKES S4/S5, src/trailmend/graph/schema.py |
| 2026-11-14 | Node natural keys carry the seed (`team:s7-aurora`, not `team:aurora`) | Ids are a hash of the natural key, so two seeds that drew the same name produced the same id and silently merged into one node when loaded into the same HydraDB graph — the first load of seed 7 after seed 1 added 893 nodes instead of 1165. Seeds are now disjoint in ids and edges and can share one graph. | evidence/load.json, tests/unit/test_northwind_generator.py |
| 2026-11-14 | The quarantine window (`recent`) is stored on the edge as a string of C and B codes, not kept in process memory | `should_quarantine` reads the last `window` judgements, so blame has to accumulate across rounds and survive a restart. Holding it in memory would also leave the product API unable to quarantine anything. A missing property reads back as null (S20), so the column was added without a migration. | PRD §6, src/trailmend/graph/state.py |
| 2026-11-14 | C3a settled before any Mend run: a template whose gold is a set returns every answer tied at minimum cost (costs compared after rounding to 1e-9); correct means the returned set exactly equals gold, and set-F1 is reported alongside. Single-answer templates still refuse a tie as `ambiguous_answer`. Credit for a set answer: blame the chosen path of each wrong member, confirm the cheapest gold path of each missed gold member, confirm the path of each correct member. | PRD §7 step 2 says ties refuse, PRD §9 says set-F1 is reported for multi-answer templates; at round 0 this left 31 of seed 7's 340 held-out questions refused purely because every edge still costs 1.0. Refusing them would have measured the tie-break rule, not the Mend. | docs/TASKS.md C3a, PRD §7, §9, user decision 2026-11-14 |
| 2026-11-14 | INV6 reads as: each random arm mirrors the mechanism arm it controls, not the whole `full` plan. `random_reweight` makes exactly the reweights `full` planned this round — same count, same signal tuple per change, so same magnitude and direction — on edges drawn without replacement from the graph's edges by a seeded RNG, and no quarantines. `random_quarantine` likewise mirrors only `full`'s quarantines. Their question ids are prefixed `random:` in the receipts. | A control has to isolate one mechanism. A single random arm carrying both reweights and quarantines would answer "does any change of this size help?" but could not say which half of the Mend the effect came from, and the task names two random arms pairing with `reweight_only` and `quarantine_only`. The `random:` prefix keeps a random receipt from ever reading as real credit for an edge. | docs/TASKS.md D3, tests/unit/test_mend_policies.py, tests/live/test_round.py |
| 2026-11-14 | `quarantine_only` applies the quarantines `full` planned but not the cost changes, which means its `recent` window never fills across rounds, so it can only quarantine on blame concentrated inside a single round. | The quarantine test reads the persisted `recent` window, which only grows when a reweight is applied. Applying reweights to make quarantine fire would stop the arm being an ablation of reweighting. The arm is weaker by construction and is reported as such rather than silently helped. | src/trailmend/loop/policy.py, src/trailmend/core/update.py `should_quarantine` |
